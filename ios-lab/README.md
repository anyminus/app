# AnyMinus iOS Audio Lab — 0.1.0

Экспериментальный нативный прототип в ветке `ios-audio-lab`. Веб-приложение, API, Cloudflare, Supabase и production-деплой не изменяются.

## Цель
Проверить на физическом iPhone, может ли нативное управление AVAudioSession сохранить качество и громкость фонограммы во время записи камеры и микрофона. Это не полноценное приложение AnyMinus и не доказательство устранения ограничений iOS. CarPlay, Bluetooth и аппаратные маршруты могут менять режим звука.

## Сборка
macOS, Xcode 16+, XcodeGen:
```sh
cd ios-lab
xcodegen generate
open AnyMinusAudioLab.xcodeproj
```
Выбрать физический iPhone, назначить собственную Apple Developer Team и уникальный Bundle ID при необходимости. CI собирает симулятор без подписи. Для TestFlight требуется Apple Developer Program, запись приложения в App Store Connect, подпись и архивирование; секреты в репозиторий не добавлять.

## Протокол проверки (SDD)
1. Импортировать локальную MP3/M4A фонограмму и начать воспроизведение.
2. Оценить звук до активации микрофона. Подготовить камеру и сравнить громкость и качество после перехода в playAndRecord.
3. Записать 20–30 секунд с голосом, сравнить звук во время записи и после отключения микрофона.
4. Повторить в режимах default и measurement, с включённым/выключенным предпочтением встроенного микрофона; сохранить сведения о входе, выходе и частоте дискретизации.
5. Повторить на динамике, проводных/BT-наушниках, CarPlay (если безопасно, автомобиль неподвижен). Не считать поддержку маршрута гарантированной.
6. Сохранить исходную запись и тестовый MP4-микс через системное меню. Проверить начало/конец, уровень звука и рассинхрон.

## Ограничения и критерии
- AVAudioPlayer + AVFoundation; AVCaptureSession не перенастраивает аудиосессию автоматически.
- Фонограмма циклическая для длительного теста, микс использует приблизительную отметку позиции при старте записи. Точная компенсация задержки, контроль клиппинга, эффекты, текст и водяной знак ещё не реализованы.
- Микрофон может акустически повторно захватывать фонограмму при работе динамика. Исходник нужен для сравнения.
- Критерий перехода к полноценному приложению: проверка на устройстве без неприемлемого приглушения/артефактов и с измеренным рассинхроном, затем проектирование AVAudioEngine и Capacitor-моста к сохранённому React UI.
- Никаких сетевых запросов, каталога, авторизации и аналитики в этом первом тесте.
