# Frontend architecture

## Lyrics verification failure handling (0.5.100)
For tracks without a ready audio pair or confirmed capability, on-demand verified metadata resolves LRC/TEXT/NONE. The provider adapter distinguishes authenticated explicit absence from transport or malformed responses. The client makes at most two verification attempts under a shared 45-second abort deadline, skips automatic retries for 401/403/429, and shows service unavailability only if no confirmed result returns. Manual retry remains available. Existing stored lyrics receipts are separate; a network error is never labeled NONE.

## Combined karaoke search (0.5.99)
The browser sends one search request with limit 15. The server independently finds ready catalog matches by title/artist and requests the Yandex provider (now up to 15 tracks), merges exact IDs and prioritizes ready tracks with verified timed lyrics, then plain lyrics, then other ready, then provider-only matches. The client uses the same normalized readiness response and does not download the whole catalog. Distinct versions with different provider IDs stay separate. Actual result count depends on matches and backend deployments.

## Per-song playback settings (0.5.98)
`anyminus:remember-song-playback` defaults true. Each numeric provider track ID has a validated `anyminus:song-playback-v1:<id>` localStorage entry, independent of cache and other tracks. Initialization priority: validated explicit shared-link parameters, saved song settings when enabled, then 100% music/15% vocals/unmuted/pitch 0/speed 1.0. The keyed LiveCatalog owns its playback state and writes a complete snapshot only on manual mixer/mute edits or successful pitch/tempo edits; initialization/failure does not write. Opening a shared link alone never overwrites personal settings; manual edits can save the resulting settings. Disabling the preference skips reads/writes without deleting saved entries. Legacy global mixer keys are ignored and the obsolete settings mixer is replaced by a default explanation. Theme, lyric preferences, video recording preferences and position are not per-song playback settings. No API or audio format changes.

## Search entry focus and home readiness label (0.5.97)

## Immediate search focus (0.5.96)
The home Find song action calls the existing hash navigator and synchronously commits the parsed route using React DOM flushSync, then focuses the mounted input and places its caret at the end. This preserves the trusted click activation needed by mobile Safari for its keyboard; it does not use a delayed effect or hidden proxy input. The normal hashchange listener remains responsible for other navigation. Search history, prior query and the search debounce are unchanged. E2E checks focus within the bubbling click and direct keyboard input; native iOS keyboard visibility is a device-level check.

## One-time cover onboarding (0.5.95)
`useCoverCoach` stores the first eligible impression in `anyminus:cover-background-coach-v1` and retains a session fallback when storage is unavailable. The non-modal anchored tip appears after stems and header artwork are ready, outside recording mode and before the song ends. Cover activation dismisses the tip and continues toggling the existing shared background preference; Got it does not change that preference. The tip does not resize the lyric viewport or block transport, and reduced-motion preferences disable the entrance animation. No API or account storage changes.
