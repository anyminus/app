# Frontend architecture

The catalog, search, track metadata, karaoke status, audio and lyrics use the configured HTTPS API. No fictional content or generated audio in the runtime. Browser preferences and real track references are local until authenticated server synchronization is available. API errors are explicit. Design system uses semantic CSS variables and reusable components; the player uses one clock and two gain nodes.

## Karaoke line motion (0.4.4)
The audio clock and active-line selection are unchanged. Timed lyrics use a 100% visual scale for the active line, 75% for every other line, left-anchored inner text transforms, and 480 ms eased transitions. Button layout remains fixed so wrapping and scroll geometry do not jump. Automatic centering uses a normalized critically damped spring-like requestAnimationFrame curve over 480 ms (inspired by https://animejs.com/easing-editor/spring/default, without a new runtime dependency). New active lines retarget from the actual scroll position; unmount, disabled autoscroll, wheel and touch cancel pending scroll. Resize/focus changes center without animation. Reduced-motion preferences disable transitions and use immediate centering. Plain unsynchronized lyrics, click-to-seek and audio/lyrics synchronization are unchanged. Browser tests cover scale, scroll isolation and reduced motion.

### Motion tuning and maintenance
Keep the outer `.lyric` button at full-size layout and apply transforms only to its `.lyric-text` span. `src/styles.css`: scale 0.75/1, `transform-origin: left center`, 480ms `cubic-bezier(.18,.78,.24,1)`; color and opacity 420ms `cubic-bezier(.2,.75,.25,1)`. `src/lyrics.mjs`: `lyricScrollEase(t)` = normalized `1-(1+7t)exp(-7t)` with exact endpoints and no overshoot. `src/LiveCatalog.tsx`: one cancellable RAF, 480ms, target clamped to the lyrics viewport; no page scroll. This is a deterministic damped easing, not an imported Anime.js runtime. Manual input cancels current scroll; automatic following resumes on the next active-line change if enabled. See [acceptance and regression checks](acceptance-0.4.4.md).

## Ready notification WebSocket (0.5.0)
Foreground App-level watcher opens one WSS connection for the current set of locally pending tracks other than the actively viewed track. Request a short-lived origin-bound ticket over existing authenticated HTTPS; pass via WebSocket subprotocol, never a URL or the bearer itself. Server events contain only public track ID; confirm through existing status API before showing the same notice. Ignore unsolicited IDs, preserve pending state and direct navigation. Connected: reconcile every 60s and on focus/reconnect; unavailable: fallback every 10s and reconnect with bounded 10–60s backoff. Ping/pong plus handshake timeout; close and cancel on subscription changes/unmount. Hidden tabs pause status reads, resume on foreground; no closed-site push. Existing current-player processing remains unchanged. Test mocked socket receipt and isolation alongside old fallback test. Core DO migration required for real WSS; fallback works during rollout. No DB change.

## Shared pitch control (0.5.1)
MDN AudioBufferSourceNode detune/playbackRate and W3C Web Audio 1.1 confirm speed changes also affect pitch/duration; HTMLMediaElement preservesPitch changes tempo while holding pitch, not independently changing key. Implement actual pitch shift via pinned MIT signalsmith-stretch 1.3.2 (WebAssembly/AudioWorklet; upstream web/release README). One live stereo processor after both independent gains; initial playback remains direct, dynamically load DSP on first nonzero selection, retain buffers and position, resume if previously playing. Processor rate remains 1 and returned live latency offsets media clock and output gate; pause/seek/recovery retain key, no additional media downloads. Initial activation may briefly interrupt playback; subsequent steps schedule in existing processor; returning to 0 retains processor for current song. New song starts at 0. Range -6..+6 semitones, one per click, chosen default; disable control when AudioWorklet unavailable, show errors on init timeout, keep unchanged dry audio if preparation fails. No backend changes. E2E tests use synthetic 440 Hz tone to verify measured output near 494 Hz at +2, duration, no downloads, compact layout. Device acceptance (particularly iPhone Safari, DSP latency and audio quality) pending. Sources: https://www.w3.org/TR/webaudio/ https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet https://github.com/Signalsmith-Audio/signalsmith-stretch/blob/main/web/release/README.md .

## Playback speed (0.5.4)
Add an equal-style speed +/- panel beside pitch, with original 1.0x and 0.5–1.5x in 0.1 steps. Both AudioBufferSourceNodes use exactly the same rate; their live mixed output is compensated by the existing Signalsmith pitch shifter using userSemitones - 12*log2(rate) (upstream live input ignores DSP schedule rate). Shared lock prevents concurrent pitch/rate/seek and suppresses stalled-clock false positives during transitions. A new track resets speed to 1. Compact layout stacks mixer above both control panels on narrow/landscape screens. DSP unavailable: both independent controls disabled. Existing pitch test remains; add actual frequency and source-clock/rate browser regression plus countdown unit tests. No Core change. Device audio quality and publication require verification.

## Optional playback settings in shared track links (0.5.5)
The track share sheet has an unchecked-by-default «Передать настройки воспроизведения» checkbox. Explicit opt-in serializes six bounded fields (music/vocals 0–100, mute flags 0/1, pitch -6..6, speed .5..1.5 with .1 step) into the hash query of /track/:id. Same generated URL is used for preview, clipboard and native share. Share from the player captures the actual mixer/pitch/speed; list shares use personal volume and original pitch/speed. No auth, position, personal identifier, or network-side storage. Validate all six fields atomically; reject malformed, duplicate or out-of-range data and retain ordinary link behavior. Received volumes/mutes are local to the current player, never overwrite persistent personal settings. A different preset (or plain link for the same track) remounts that player. Prepare a single DSP with both pitch and rate before starting the stems; if initialization fails, keep original pitch/rate, retain shared mixer, show a warning. Artist shares unchanged. Unit and browser tests cover opt-in link, received controls, mute, legacy and isolation. No Core change. Live and mobile verification pending.
